The CLI uses workflow states (todo, in-progress, blocked, review, closed) that differ from GitHub's open/closed model. This causes confusion:

1. Users expect --status open (GitHub convention) but we only accept workflow states
2. AI agents expect terminology aligned with GitHub
3. The distinction between our workflow model and GitHub's state model is not clearly documented

## Solution
- Add explicit documentation explaining that roadmap statuses are workflow stages, not GitHub open/closed states
- Clarify in help text and examples what each status means in workflow context
- Consider adding aliases (open -> todo|in-progress, closed -> closed) with clear documentation that these are convenience mappings

## Impact
Reduced user confusion, better AI agent compatibility, clearer mental model for roadmap planning.
