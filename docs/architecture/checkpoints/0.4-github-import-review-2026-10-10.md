# Bounded GitHub importer: pre-commit architecture review

Reviewed 2026-10-10 against ADRs 0001–0006 and 0012, the completed migration
baseline, and the pending importer patch. No architecture-boundary regression
was found. This is local candidate evidence, not a release or remote CI result.

## Responsibility review

| Boundary | Implementation | Finding |
| --- | --- | --- |
| Inbound CLI | `roadmap/adapters/inbound/cli/github.py` | Parses selection/apply, invokes Application, renders JSON and the standard stale-projection warning. No provider extraction or persistence implementation imports. |
| Application | `roadmap/application/use_cases/github_import.py` | Owns the narrow source port, source/result DTOs, validation, qualified identity ownership, immutable revision deduplication and batch transaction decisions. Imports only Application, Domain and the standard library. |
| Outbound GitHub | `roadmap/adapters/outbound/github/issues.py` | Owns `gh api`, subprocess timeouts, pagination and extraction errors. Does not write local files, instantiate persistence, or mutate GitHub. |
| Canonical persistence | Existing issue unit-of-work port and implementation | Sole write path. Existing lock, transaction recovery, unknown-frontmatter preservation and projection refresh are reused. No second database, journal or writer introduced. |
| Composition | `roadmap/bootstrap/core.py` | Selects the reader and injects it, the unit-of-work factory and clock into the Application use case. No matching or import business rules added. |

Domain and persistence production modules are unchanged. GitHub envelope fields
remain source evidence in an Application-owned DTO and attributed issue comment;
no provider-shaped Domain entity or workflow status is introduced. Keeping
provider-specific source validation in this deliberately bounded ingestion use
case is consistent with ADR-0012; it does not create a generic integration
framework. Protocol placement follows the existing closure-publication use case.

The duplicate-owner label makes a previously recorded human disposition explicit.
It is validated before matching; it does not exempt closed/archived issues or
silently pick a winner. Source capture does not publish closures or perform
GitHub-only status reconciliation. Ordinary commands remain offline.

No direct runtime dependency was added. Architecture contracts, removed-namespace
guards and the empty exception baseline are unchanged. Policy-test edits add the
new capability and command safety contract without reducing existing assertions.

## Verification

- Architecture checker: 148 files, 566 dependencies; all four Import Linter
  contracts kept, zero broken, with the existing supplemental guards passing.
- 315 scoped tests passed: importer and existing publication paths, persistence,
  and the entire policy suite (including negative architecture fixtures).
- Type checking, Ruff lint and formatting passed.
- Existing repository Xenon limits passed unchanged: maximum block/module B,
  average A. Importer-related modules average A (3.97); highest block score B (10).
- Fresh candidate wheel installed in an isolated temporary environment passed
  the importer journey: stable local ID, zero canonical writes on unchanged
  repeat, two distinct source revisions and local planning decisions preserved.
- `git diff --check` passed.

The live preview matched all 11 frozen GitHub reports to existing canonical IDs,
including the original #3676 record after explicit duplicate ownership was
recorded through Roadmap. Live apply/repeat proof is still pending.

## Limits and remaining work

These checks do not substitute for the supported Python/Linux/macOS CI matrix or
live batch apply evidence. The candidate still reports package version 0.3.1;
it is unreleased 0.4 development code. The working tree also contains separate
`uv.lock` development-tool upgrades; they were not required by the importer and
are outside this feature's intended commit. Local checks used that working lock.
