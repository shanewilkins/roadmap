# Roadmap 0.2.0 release checklist

Status: **prepared, not authorized or published**.

The release is performed only from a clean, reviewed commit after Phase 13 is
accepted. PyPI artifacts are immutable, so every item is a hard gate.

## Candidate verification

- [ ] Phase 13 checkpoint is committed and all listed checks are green.
- [ ] The complete post-refactor suite meets the 78% coverage floor.
- [ ] `git status --short` is empty and the intended commit is on `main`.
- [ ] `architecture.toml` records final Phase 13 acceptance with no baseline
  exceptions.
- [ ] Requirements, public contract, compatibility inventory, README, CLI help,
  migration guide, and changelog agree on the 0.2 boundary.
- [ ] Wheel and source distribution build from the clean checkout.
- [ ] Both artifacts pass isolated import, version, help, initialization,
  creation, and list smoke tests.
- [ ] The wheel passes the cumulative 0.1.1 migration and retained-user journey.
- [ ] The full suite is green on Python 3.12, 3.13, and 3.14 on Ubuntu 24.04
  x64; exact built artifacts pass installed journeys on Python 3.12 and 3.14 on
  Ubuntu 24.04 x64 and macOS 15 ARM64.
- [ ] Artifact contents contain no `.roadmap`, test, cache, secret, build, or
  development-only files.
- [ ] Artifact metadata names `roadmap-cli`, version `0.2.0`, Python
  3.12/3.13/3.14, macOS/Linux, MIT, and the correct repository URLs.
- [ ] Release notes call out the explicit migration and remote-sync removal.

## Authorized release actions

Do not perform these during Phase 13 preparation. After explicit authorization:

1. Change `pyproject.toml` from 0.1.1 to 0.2.0 and move the changelog entry from
   Unreleased to `0.2.0 - YYYY-MM-DD`.
2. Run `uv lock`, the focused/static release checkpoint, artifact smoke tests,
   and cumulative installed journey again.
3. Commit only the reviewed version/changelog/lock changes.
4. Create and push annotated tag `v0.2.0` at that commit.
5. Let `.github/workflows/release.yml` build once and publish through the PyPI
   `pypi` environment using OIDC trusted publishing. Do not upload locally.
6. Verify `pip index versions roadmap-cli`, install 0.2.0 into a clean
   environment, and repeat `--version`, `--help`, init, and migration smoke.
7. Create the GitHub release from the accepted changelog and migration warning.

## Trusted-publishing controls

- PyPI project: `roadmap-cli`.
- GitHub repository: `shanewilkins/roadmap`.
- Workflow: `.github/workflows/release.yml`.
- Environment: `pypi`.
- The publish job has only `id-token: write`; repository contents remain read
  only and no long-lived PyPI token is stored.
